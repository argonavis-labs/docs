---
title: "Create your own Runner"
description: "Turn one repeated job into a Runner with a prompt, schedule, and clear permissions."
---

There are two ways to create a Runner:

1. Fill in the form yourself.
2. Ask Runner to help you design it.

Use the second one when the job is still fuzzy. Use the form when you already know the prompt and schedule.

<Warning>
  **A new Runner is active as soon as it's created.** Review the prompt, schedule, timezone, Project, intelligence, and tool permissions before you finish. A scheduled time can arrive before you come back to edit it.
</Warning>

## Ask Runner to build it with you

<Steps>
  <Step title="Start the setup">
    Open **Runners**, click **New runner**, then choose **Ask Runner to create it**.
  </Step>
  <Step title="Describe the job">
    Say what you want, when it should run, and what a useful result looks like. Add this line when you want a review before creation:

    ```text
    Ask me whatever you need. Show me the final prompt, schedule, timezone,
    Project, and intelligence setting. Wait for my confirmation before you
    create the Runner.
    ```
  </Step>
  <Step title="Check the final setup">
    Read the proposed prompt and schedule. Confirm only when you're ready for the Runner to become active.
  </Step>
</Steps>

## Fill in the form yourself

Open **Runners**, click **New runner**, then choose **Create manually**.

Fill in:

- **Name**
- **Prompt**
- **Schedule** and **Timezone**
- **Project**, when the job belongs with other work
- **Runner model**, using **Normal** or **Ultra**

Click **Create runner** only after you've checked the schedule. The new Runner starts active.

## Check permissions before the first run

For connected-app writes:

- **Ask** stages an **Action Card** for review.
- **Allow** performs the action without asking.
- **Off** blocks the tool unless this Runner has its own override.

A user-created Runner can override the baseline setting under its own **Tool permissions**. Anything left on **Inherited** uses the connected account's setting.

Start writes on **Ask** when you're testing a new Runner. Move a specific tool to **Allow** only when you want that Runner to use it without stopping for review.

[How tool permissions work →](/connections/tool-permissions)

## Decide what carries forward

Each run starts in a separate session. Previous run output is not automatically supplied to the next one.

Use Personal Memory for durable facts. Use Project context for standing instructions about the work.

The **Carry unresolved Action Cards into new runs** switch does one narrower job. It lets an unresolved **Action Card** appear in a later run. A pending **Action Card** still expires 24 hours after it was staged.

## Test it

Open the Runner and click **Run now**. The test appears as a new session, even if the Runner is paused.

Check the result, tool activity, and any **Action Cards**. Then leave the schedule active, or use the **Status** switch to pause it while you adjust the prompt.
